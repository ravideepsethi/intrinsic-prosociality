# Stage 09 v1.1 QA resolution

## Exact-zero hardening

Stage 09 v1.0 revealed 244,300 standard-fair observations with chooser draw
payoff exactly equal to zero. Version 1.1 added:

- `tableR11_exact_zero_payoff_descriptives.csv`; and
- `tableR12_exact_zero_payoff_models.csv`.

The new models exclude exact zeros or give exact zero its own category. The
strictly positive coefficient remains 0.410 percentage points in the two-point
window and 0.446 points in the six-point window, with t-statistics above 53.
Exact zero also has a positive coefficient of approximately 0.37--0.38 points.
Thus the main favorable/non-loss result is not mechanically generated by the
zero mass.

The v1.1 pilot and full 24-month producer both completed their internal QA and
wrote certified success receipts. The full output has:

- status `STAGE09_PANEL_ROBUSTNESS_24M_CERTIFIED_OK`;
- 47,587,020 rows and 47,587,020 unique game IDs;
- success-receipt SHA-256
  `5107e4dabd11054724691f6c3c6937e495b8b15648302ecd578217e81d55b6e7`;
  and
- 13-file manifest SHA-256
  `2321277ae52a54629919c9e982a4c16a6dcf5bfaeaf62c74dbf74366693150a9`.

After certification, the launcher attempted to require byte-identical copies of
all eleven v1.0 CSV files. That external comparison failed on the density CSV.
The producer output itself had not failed.

## Semantic-equivalence recovery

The recovery audit authenticated both success receipts, both manifests, and
every file against its recorded byte count and SHA-256. It then compared the
eleven common CSVs by schema, row order, exact text fields, exact integer
counts, missing-value locations, and numerical values using `rtol=1e-12` and
`atol=1e-10`.

- Nine common files were byte-identical.
- `figureR01_draw_payoff_density.csv` differed only in parallel floating-point
  mean aggregation, with maximum absolute difference `1.021e-14`.
- `tableR08_economic_magnitude.csv` differed only in floating-point aggregation,
  with maximum absolute difference `1.863e-08` in an aggregate magnitude.
- All other values, labels, shapes, and schemas matched.
- The only new manifest paths were Tables R11 and R12.

The semantic audit therefore ended with
`STAGE09_V110_SEMANTIC_EQUIVALENCE_OK`. Requiring byte identity for parallel
floating-point aggregates was an unnecessarily strict launcher condition; it
is superseded by the typed semantic-equivalence check. Version 1.1 is the
canonical Stage 09 panel-robustness output. Version 1.0 remains preserved as an
audit predecessor.

## Opening-plan Git-head correction

Version 1.1 also added an authenticated `--expected-git-head` argument to the
opening-plan and opening-analysis producers. The current producers recognize
and fully reauthenticate the exact certified v1.0 opening-plan receipt with
SHA-256
`2c8bc601d50e23fa55e9f3d09969096cd5212177c31eb6e508dc699ec95a38ca`.
This prevents a later repository commit from mechanically invalidating the
already-certified target catalog while still requiring launchers to state the
approved current Git identity.
