# Disruption screen v1.0.0 — fixed before production

Purpose: find candidate common technical disruptions in the existing archive. No kindness outcome, Patron status, future behavior, or rating cost enters event discovery or ranking. The scan does not presume that generosity rises during an outage or that board position ceases to matter.

**Input frame.** The requested period is 1 November 2023 through 31 October 2025, UTC. The preferred source is completed canonical Stage 04 API response Parquets, including `timeout` and `outoftime`. The eleven earlier months may instead use the historical curated Parquet selector if those selected files contain every required raw API field and reconcile to the frozen monthly counts. Sources are never concatenated within a month. Missing, incomplete, incompatible, or failed months are reported explicitly. No API retrieval, PGN download, Stockfish evaluation, source-file modification, or timeout-only fallback is performed.

This frame consists of API-enriched time-forfeit candidates selected by the upstream construction. It is not an independently observed disconnection census. Ordinary clock expirations are included; games that resume or are aborted or absent from the archive can be missed. The five-second upstream screen can also omit disruptions. A lack of candidates is not evidence that no outage occurred. Exact completeness of a physical-disconnection universe is not asserted.

**Time and identity audit.** Require raw API creation and last-move times in milliseconds, exact game IDs, both player-name fields, status, speed, rated flag and variant. Check uniqueness, same-month creation, alias agreement and valid IDs. Keep rated standard realtime games with `timeout` or `outoftime`, lastMoveAt at or after creation, duration at most seven days, and lastMoveAt inside the analysis period. Timestamps outside this support are audited, not rescaled or imputed. Exclude a source month from detection if more than 0.1% of raw records have impossible/missing/>7-day timing, more than 2% have missing or identical accounts, or either discovery/validation sample has fewer than 1,000 games. Games with missing names remain in all-group diagnostics but never determine the screen. Seven days after a coverage boundary are excluded from detection so unobserved earlier-starting games cannot create artificial low baselines. This is a conservative coverage rule, not a behavioral restriction.

Raw lastMoveAt is a timing proxy, not a verified connection-loss or claim-click timestamp. The program reports second/minute rounding and timestamp bunching. Ten-second histograms are diagnostics only. The timestamp's semantic reliability must be reviewed before describing players as disconnecting simultaneously.

**Disjoint player sets.** Assign each normalized username a deterministic bit from the first hexadecimal digit of MD5(`disruption-v100| ` + username), using `(digit+1) mod 2`. Games with both players in group 0 form discovery; games with both in group 1 form validation. Games crossing groups enter neither detection nor validation. Thus no account appears in both samples. Common temporal shocks can still affect both groups; replication is not a formal independent p-value or proof of an outage. The game-level split is never based on outcome or source availability.

**Detection.** Count the combined `timeout` and `outoftime` endpoints by minute for all realtime speeds pooled and for each of five speed strata. Screen one-minute and centered five-minute counts. Compare with the same UTC weekday/minute at −28, −21, −14, −7, +7, +14, +21 and +28 days. Require at least four valid comparison windows. Reference values are summarized by their median and median absolute deviation.

When every usable API month has validated canonical chronology inputs, rescale each reference count by the ratio of archived realtime game starts in the 50-minute interval from 60 to 10 minutes before the focal versus reference minute. Require at least 100 starts in each interval and traffic ratios between 0.25 and 4. The volume proxy pools speeds; separate-speed scans remain exploratory checks. It is not an exact denominator of concurrent games at risk. Contemporary start counts do not enter this rescaling, to avoid mechanically increasing an anomaly score during a collapse in starts. If chronology is unavailable for any usable month, the entire primary screen uses the same-weekday/minute baseline without this rescaling; the report labels that mode. Available start counts are still plotted diagnostically.

Score = (observed − reference median) / max(sqrt(reference median + 1), 1.4826 × reference MAD). This is an exploratory anomaly score, not a calibrated z-statistic or p-value. Require score ≥8, ratio observed/max(median,5) ≥2.5, excess ≥50, and at least 100 discovery games. Search both time scales and all six speed series. The many scanned windows do not receive a claim of familywise statistical significance.

Sort passing windows by discovery score, then excess, time, series and width. Greedily retain up to 30 episodes, requiring more than 30 minutes between selected centers. Both the selection rule and the actual selected list are written before inspecting validation counts. This is a ranked shortlist, not an exhaustive incident count; the 30-minute separation can combine nearby disruptions.

**Validation and review.** At each frozen minute, series and scale, evaluate group 1 using its own reference median/MAD and the same traffic rule. Mark temporal replication if validation score ≥4, ratio ≥1.5, and excess ≥20. Never reorder or expand the episode list using validation outcomes. Report distinct accounts/pairs, the largest account's share of games, exact timestamp concentration, ten-second counts, terminal-status counts, speed mix and archived game starts. Flag episodes where one account supplies more than 5% of discovery or validation games in the screened series. These diagnostics do not independently verify the cause. No external outage is declared by the code.

**Main-panel overlay.** If the authenticated 41,534,331-row main panel is available, report how many observed choices fall inside the selected window, their board-state counts, and remaining-clock summaries. The overlay does not read the kind-draw column and cannot alter the shortlist. It is not a population disconnect-rate estimate. No claim that both players remained able to act is inferred solely from the common event.

**Output and interpretation.** A report ZIP contains only aggregate diagnostics, UTC candidate times, plots, execution status and an empty incident-review template. Private game-level caches and player names stay on the external drive. Next steps require checking independent incident evidence and whether a connected opponent still had a real decision. An outage can help address selection into disconnection; it does not randomly assign receipt of kindness, remove the relevance of board position, or automatically satisfy an IV exclusion restriction.

**Reproducibility.** Input Parquet bytes are hashed before reuse. New monthly caches are bound to input digests, parameters and the package code manifest, and outputs are rehashed before resume. Original chronology authority pins size, rows and row groups; current full-content hashes are recorded separately rather than presented as old certified hashes. Individual month failures produce an explicit incomplete-coverage report; missing periods do not become zero observations. The candidate screen is recomputed on each attempt. Its successful execution is distinct from the substantive existence of validated outages.
